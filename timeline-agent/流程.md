# Agent 助手开发流程

## 目标
开发一个小说创作 Agent 助手，自动保存故事线和人物列表到文件中，AI 创作章节时从文件中提取故事背景和人物人设生成内容。

## 阶段五：从"AI工具"升级为"真正的Agent" 🚧 待开发

> **当前状态**：AI 是被动响应的——用户点"生成"，AI 返回文本，不能操作数据，不会自主决策。
> **目标状态**：AI 能自主思考、调用工具操作数据、多步推理、自动完成复杂任务。

---

### 5.1 Function Calling（工具调用）— 最关键

让 AI 不只是生成文本，而是能**直接操作项目数据**。

**需要做的事**：
- [ ] 5.1.1 定义工具列表（tools schema），供 LLM 识别和调用：
  ```
  🔧 数据查询类：
  - get_characters()          → 获取所有角色列表
  - get_character(id)         → 获取某个角色详情
  - get_events()              → 获取故事线事件树
  - get_event(id)             → 获取某个事件详情
  - search_characters(query)  → 按名字/特征搜索角色

  🔧 数据操作类：
  - add_character(data)       → 创建新角色
  - update_character(id,data) → 修改角色设定
  - add_event(parentId,data)  → 添加故事事件
  - update_event(id,data)     → 修改事件
  - delete_event(id)          → 删除事件

  🔧 创作辅助类：
  - generate_chapter(prompt)  → 生成章节内容
  - check_consistency(content)→ 一致性检查
  - save_version(content)     → 保存版本记录
  ```
- [ ] 5.1.2 后端实现工具执行器：解析 LLM 返回的 tool_call，执行对应操作，返回结果
- [ ] 5.1.3 工具执行结果同步回前端（操作数据后触发 Store 更新）

**产出**：AI 说"我来创建一个角色"，就能真的在角色列表里出现。

---

### 5.2 Agent 推理循环（ReAct 模式）

让 AI 从"单轮问答"变成"多步自主推理"。

**需要做的事**：
- [ ] 5.2.1 实现 ReAct 循环：`思考 → 调用工具 → 观察结果 → 再思考 → 再调用... → 最终回答`
  ```
  用户: "帮我写第三章，让张三和李四和解"

  🤔 思考: 需要先了解张三和李四的设定
  🔧 调用: get_character("张三") → {性格: 记仇, 背景: 被背叛过}
  🔧 调用: get_character("李四") → {性格: 冲动, 背景: 做错事后悔}
  🤔 思考: 张三记仇但李四后悔，和解需要契机，先看当前故事线
  🔧 调用: get_events() → [事件列表...]
  🤔 思考: 可以设计一个共同危机作为和解契机
  🔧 调用: generate_chapter("第三章：暴风雨中的和解...")
  🤔 思考: 生成完毕，检查一致性
  🔧 调用: check_consistency(generated_content)
  🤔 思考: 一致性通过，添加新事件到故事线
  🔧 调用: add_event(null, {title: "第三章：和解", ...})
  ✅ 完成: 章节已生成并添加到故事线
  ```
- [ ] 5.2.2 循环终止条件：AI 返回最终回答，或达到最大步数限制
- [ ] 5.2.3 每一步的中间过程通过 SSE 流式推送到前端，让用户看到 Agent 的"思考过程"

**产出**：AI 能自主拆解任务、多步执行，而不是等用户一步步指令。

---

### 5.3 自动规划（Planning）

用户给一个大目标，AI 自己拆解成执行计划。

**需要做的事**：
- [ ] 5.3.1 设计规划 Prompt：让 AI 把用户目标拆解为可执行的步骤列表
  ```
  用户: "帮我构思一个10章的悬疑小说"

  📋 执行计划:
  1. 确定故事主题和核心悬念
  2. 创建3-5个关键角色
  3. 设计10章的故事线大纲
  4. 逐章生成详细内容
  5. 全局一致性检查
  ```
- [ ] 5.3.2 前端展示执行计划，用户可以确认/修改/跳过某步
- [ ] 5.3.3 Agent 按计划自动执行，每步完成后更新进度

**产出**：用户给一句话目标，Agent 自动完成从构思到成稿的全流程。

---

### 5.4 长期记忆（Memory）

让 Agent 记住之前的创作决策和用户偏好。

**需要做的事**：
- [ ] 5.4.1 设计记忆数据结构：
  ```
  memory.json:
  - 创作决策: [{ 决策, 原因, 时间 }]
  - 用户偏好: { 叙事视角, 文风, 章节长度, ... }
  - 对话摘要: 每次会话的要点总结
  - 修改历史: 用户对生成内容的修改模式（偏好什么风格）
  ```
- [ ] 5.4.2 每次对话开始时，自动注入相关记忆到 system prompt
- [ ] 5.4.3 对话结束后，自动总结并保存到记忆文件

**产出**：Agent 记得"上次你说喜欢第一人称叙事"，不会每次从零开始。

---

### 5.5 前端 Agent 交互升级

配合后端 Agent 能力，升级前端交互。

**需要做的事**：
- [ ] 5.5.1 思考过程展示：实时显示 Agent 的推理步骤（思维链可视化）
  ```
  🤔 正在分析角色设定...
  🔧 查询角色: 张三、李四
  🤔 正在构思情节...
  🔧 生成章节内容
  🤔 正在检查一致性...
  ✅ 一致性检查通过
  🔧 添加事件到故事线
  ```
- [ ] 5.5.2 执行计划面板：展示当前计划，支持用户确认/修改
- [ ] 5.5.3 工具调用确认弹窗：危险操作（删除角色/事件）需用户确认
- [ ] 5.5.4 Agent 操作结果实时同步：AI 创建角色后，角色面板自动刷新

**产出**：用户能直观看到 Agent 在做什么，并保持控制权。

## 阶段五技术方案

| 模块 | 技术选型 |
|------|---------|
| Function Calling | OpenAI Function Calling API / 兼容格式 |
| 推理循环 | ReAct 模式（后端 while 循环） |
| 自动规划 | LLM 生成 JSON 计划 → 前端展示确认 → 后端执行 |
| 长期记忆 | memory.json + 自动摘要 |
| 思维链可视化 | SSE 推送思考步骤 → 前端实时渲染 |
| 工具确认 | 前端弹窗确认 → WebSocket/SSE 回传确认 |

---

## 阶段五开发顺序建议

```
5.1 Function Calling  ←  最核心，先做这个
    ↓
5.2 Agent 推理循环    ←  在 Function Calling 基础上加循环
    ↓
5.5 前端交互升级      ←  让用户能看到 Agent 在干什么
    ↓
5.3 自动规划          ←  更高级的自主能力
    ↓
5.4 长期记忆          ←  锦上添花
```

## 技术方案（阶段 1-4 已完成）

| 模块 | 技术选型 |
|------|---------|
| 前端框架 | Vite + TypeScript |
| 状态管理 | Zustand (vanilla) |

## 使用说明

### 启动前端
```bash
npm run dev
```

### 启动 AI 后端
```bash
npm run dev:server
```

### 同时启动前后端
```bash
npm run dev:all
```

### AI 配置
1. 编辑 `server/.env`，填写你的 API Key
2. 或在前端 AI 助手面板点击 ⚙ 按钮配置
3. **阿里云通义千问**（默认）：
   - API 地址：`https://dashscope.aliyuncs.com/compatible-mode/v1`
   - 模型：`qwen-turbo` / `qwen-plus` / `qwen-max` / `qwen-long`
   - API Key：在 [DashScope 控制台](https://dashscope.console.aliyun.com/) 获取
